# ADR-0005: Offline-First with Authoritative Sync

**Status:** Accepted
**Date:** 2026-08-01

## Context

School-level operations (attendance marking, library borrowing, notification queueing, audit buffering, reporting reads) must work where connectivity is unreliable. Irreversible or numbering-critical operations (graduation, certificate issuance, gradebook publication, academic year activation, refunds) require authoritative confirmation.

The interaction architecture defines three offline modes: fully offline-capable, offline with server confirmation, and authoritative sync required.

## Decision

Adopt **offline-first** operation:

- Every aggregate carries `version`, `lastModifiedAt`, `lastModifiedBy`, `syncVersion`, and `deviceId`.
- Commands carry `expectedVersion`; conflicts return explicit conflict results.
- Lifecycle and identity fields are never auto-merged.
- Offline events are queued locally in the outbox and published after successful sync.
- Authoritative operations require synchronization before becoming official.

## Consequences

**Positive:**

- Usable in low-connectivity school environments.
- Conflict detection is explicit and auditable.

**Negative:**

- Sync complexity and conflict resolution overhead.

## Rationale

Offline-first is a core requirement for school operations and is already embedded in the Student Enterprise v2 and the Enterprise Business Interaction Architecture. It must remain a first-class concern in all domain implementation.
