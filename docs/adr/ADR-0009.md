# ADR-0009: Published Language and Open Host Service

**Status:** Accepted
**Date:** 2026-08-01

## Context

Cross-context integration requires stable, explicit contracts. The Bounded Context Map defines a Published Language (commands, queries, DTOs, events, read models, error codes) and Open Host Service as the required relationship for high-value cross-context operations (Security, Notification, Workflow coordination). Without published contracts, contexts would couple to each other's internals.

## Decision

Adopt **Published Language** and **Open Host Service** for all cross-context integration:

- Each context publishes commands, queries, DTOs, domain events, read models, and error codes.
- Every integration has an owning public contract.
- Contracts are versioned; breaking changes follow the versioning and deprecation rules.
- UI DTOs are never used as integration contracts.
- High-value cross-context capabilities (authorization, notification dispatch, workflow approvals) are exposed as Open Host Services.

## Consequences

**Positive:**

- Stable integration surface and independent evolution.
- Contract tests enforce compatibility.

**Negative:**

- Contract design and registry overhead.

## Rationale

Published Language/Open Host Service is the pattern already mandated by the Bounded Context Map and reflected in the interaction architecture. This ADR makes it binding for all future contracts.
