# ADR-0008: Mandatory Anti-Corruption Layer for External, Legacy, and AI

**Status:** Accepted
**Date:** 2026-08-01

## Context

The platform must integrate with external systems (payment gateways, SMS/email/push providers, biometric/RFID devices, ministry systems, spreadsheet imports) and with legacy modules and AI/LLM outputs. These sources use foreign vocabularies, incomplete data, and unsafe payloads. The Bounded Context Map requires ACLs for all such integrations and forbids AI from mutating operational aggregates.

## Decision

Adopt **Anti-Corruption Layers** as mandatory for every external, legacy, ministry, or AI integration:

- Translate foreign IDs into local value objects.
- Normalize external status vocabularies.
- Validate external payloads before domain use.
- Protect domain aggregates from incomplete or unsafe data.
- Map external errors into application errors.
- Log rejected translations with audit metadata.
- AI/LLM outputs pass through ACL + output validation + human review (see `docs/governance/AI-Governance.md`).

## Consequences

**Positive:**

- Domain invariants protected from foreign model corruption.
- Consistent error handling and auditability.

**Negative:**

- Translation and validation overhead per integration.

## Rationale

ACL is the established pattern in the Bounded Context Map (Phase 3.1) and interaction architecture (Phase 3.2). Without it, external and AI models would leak into the domain and break single-source-of-truth ownership.
