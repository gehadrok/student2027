# ADR-0010: Shared Kernel Limited to Stable Primitives

**Status:** Accepted
**Date:** 2026-08-01

## Context

Some IDs and primitives are shared across many contexts (school scope, tenant, user, student, teacher, academic year, term, grade, section, subject, money, date range, percentage, audit metadata, event envelope, pagination, sort order). Without an explicit boundary, the Shared Kernel could grow into an accidental god-module containing aggregates, repositories, and policies.

## Decision

Adopt a **Shared Kernel limited to stable primitives**:

- Allowed: stable IDs, `Money`, `DateRange`, `TimeRange`, `Percentage`, `AuditMetadata`, `DomainEventEnvelope`, `Pagination`, `SortOrder`.
- Not allowed: aggregate roots, repository interfaces, persistence records, UI DTOs, business policies, workflow state machines.
- The Shared Kernel is small, stable, and versioned; additions require an ADR.

## Consequences

**Positive:**

- Minimal coupling between contexts.
- Clear boundary preventing shared-kernel abuse.

**Negative:**

- New shared primitives require deliberate review.

## Rationale

The Bounded Context Map already enumerates the allowed and disallowed Shared Kernel contents (Phase 3.1, §6). This ADR freezes that boundary so it cannot drift during implementation.
