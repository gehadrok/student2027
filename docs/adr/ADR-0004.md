# ADR-0004: CQRS with Projections and Read Models

**Status:** Accepted
**Date:** 2026-08-01

## Context

Cross-context reads must not use another context's aggregate repositories. Reporting, dashboards, and downstream contexts need denormalized, query-optimized views. The Bounded Context Map requires published read contracts, read models, and projections for integration, and the interaction architecture defines projection updaters that consume events.

## Decision

Adopt **CQRS** with a split between the command side (aggregate mutation through repository contracts) and the query side (projections and read models served through read repositories and published read contracts).

- Commands load aggregates, apply behavior, save with expected versions, and collect domain events.
- Queries never mutate aggregates.
- Projections are updated idempotently from the event stream (keyed by `(projection_type, aggregate_id, aggregate_version)`).
- Read models are rebuildable from the outbox/event log.
- Reporting owns cross-domain projections; each context owns its read repositories.

## Consequences

**Positive:**

- Read scalability and query-optimized models.
- No cross-context aggregate access.
- Rebuildable projections for recovery.

**Negative:**

- Eventual consistency for read models.
- Duplication of data (projections) requiring invalidation discipline.

## Rationale

CQRS is the sanctioned read path in the Bounded Context Map and Interaction Architecture, and matches the existing repository split (`I<Name>Repository` vs `I<Name>ReadRepository`) in the Student Domain Standard.
