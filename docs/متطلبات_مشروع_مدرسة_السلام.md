# وثيقة متطلبات المشروع (SRS)
## نظام إدارة "مدرسة السلام" الذكي

**الإصدار:** 1.0
**التاريخ:** يوليو 2026
**نوع المستند:** وثيقة متطلبات (Software Requirements Specification)

---

## 1. نظرة عامة على المشروع

### 1.1 اسم المشروع
نظام إدارة مدرسة السلام (Al-Salam School Management System)

### 1.2 الهدف من المشروع
بناء تطبيق ويب متكامل لإدارة العملية التعليمية والإدارية داخل المدرسة، يخدم أربع فئات من المستخدمين (المدير، المدرس، الطالب، ولي الأمر)، مع الاستفادة من الذكاء الاصطناعي في تحليل الأداء والتنبؤ والمساعدة الذكية.

### 1.3 نطاق المرحلة الأولى (MVP)
تُبنى النسخة الأولى بدون أي أطر عمل خارجية (Frameworks) للواجهة، أي باستخدام:
- **HTML5 / CSS3 / JavaScript (Vanilla JS)** فقط للواجهة الأمامية.
- **RealmDB** كقاعدة بيانات محلية (Local/Embedded Database) لتخزين البيانات على الجهاز مباشرة، مع دعم المزامنة لاحقًا إن لزم.

> ملاحظة تقنية: "عدم استخدام أطر عمل خارجية" يُقصد به أطر واجهة المستخدم (مثل React أو Angular أو Vue). أما RealmDB فهو مكتبة قاعدة بيانات (Database SDK) وليس إطار عمل واجهات، لذا فهو متوافق مع هذا الشرط.

### 1.4 الجمهور المستهدف
- إدارة المدرسة
- المعلمون
- الطلاب
- أولياء الأمور

## 2. أدوار المستخدمين والصلاحيات (Roles & Permissions)

| الدور | الصلاحيات الرئيسية |
|---|---|
| **مدير (Admin)** | صلاحية كاملة: إدارة المستخدمين، الفصول، المواد، الجداول، المالية، التقارير، الإعدادات العامة |
| **مدرس (Teacher)** | تسجيل الحضور والغياب، إدخال الدرجات، عرض جدوله، التواصل مع الطلاب/الأولياء، رفع الملاحظات |
| **طالب (Student)** | عرض جدوله، درجاته، حضوره، شهاداته، الإشعارات الخاصة به |
| **ولي أمر (Parent)** | متابعة أبنائه: الحضور، الدرجات، المدفوعات، استلام الإشعارات، التواصل مع المدرسة |

### 2.1 نظام تسجيل الدخول
- تسجيل دخول موحّد بشاشة واحدة تحدد الدور تلقائيًا حسب الحساب.
- تشفير كلمات المرور (Hashing) قبل التخزين.
- صلاحيات وصول (Role-Based Access Control - RBAC) تمنع كل دور من الوصول لما لا يخصه.
- إمكانية "نسيت كلمة المرور" واسترجاعها.
- تسجيل خروج تلقائي بعد فترة خمول (Session Timeout).
- سجل عمليات دخول (Login Log) لأغراض الأمان.

## 3. المتطلبات الوظيفية (Functional Requirements)

### 3.1 إدارة الطلاب والفصول
- إضافة/تعديل/حذف بيانات الطالب (الاسم، تاريخ الميلاد، الجنس، بيانات ولي الأمر، الصورة، الحالة الصحية إن وجدت).
- تسكين الطلاب في الفصول والشُّعب (Class / Section).
- نقل الطالب بين الفصول أو الصفوف الدراسية.
- ملف تعريف شامل لكل طالب (Student Profile) يجمع الحضور + الدرجات + الملاحظات + المدفوعات.
- إدارة الصفوف الدراسية (المستويات) والشُّعب داخل كل صف.
- البحث والفلترة المتقدمة (حسب الصف، الشعبة، الحالة، الرقم الأكاديمي).

### 3.2 إدارة المدرسين والمواد والجداول
- ملف تعريف للمدرس (التخصص، المواد التي يدرّسها، سنوات الخبرة، جدوله).
- إدارة المواد الدراسية (اسم المادة، الصف المرتبطة به، عدد الحصص الأسبوعية).
- ربط كل مدرس بالمواد والفصول التي يدرّسها.
- منشئ الجداول الدراسية (Timetable Builder) مع كشف التعارضات تلقائيًا (Conflict Detection).
- عرض الجدول حسب الفصل أو حسب المدرس أو حسب اليوم.

### 3.3 الحضور والغياب
- تسجيل الحضور اليومي لكل حصة أو لليوم الدراسي كاملًا (قابل للتخصيص).
- حالات متعددة: حاضر، غائب، متأخر، غياب بعذر.
- تقارير حضور شهرية/فصلية لكل طالب وكل فصل.
- تنبيه تلقائي لولي الأمر عند غياب الطالب.
- نسبة الحضور الإجمالية معروضة في لوحة تحكم الطالب.

### 3.4 الدرجات والشهادات
- إدخال الدرجات لكل مادة (اختبارات قصيرة، أعمال فصلية، اختبار نهائي).
- حساب المعدل التراكمي تلقائيًا حسب أوزان الدرجات المحددة.
- كشف درجات لكل طالب قابل للطباعة.
- إصدار شهادات رسمية (نجاح/تقدير/إتمام) بتصميم قابل للتخصيص وشعار المدرسة.
- تصدير الشهادات والكشوف بصيغة PDF.
- مقارنة أداء الطالب عبر الفصول الدراسية (تحليل اتجاه الأداء).

### 3.5 الإدارة المالية (المصروفات والمدفوعات)
- تسجيل الرسوم الدراسية لكل طالب (رسوم كاملة/دفعات).
- تسجيل المصروفات التشغيلية للمدرسة (رواتب، صيانة، مستلزمات).
- سندات قبض وصرف إلكترونية.
- تنبيه عند اقتراب أو تأخر موعد استحقاق الدفعة.
- تقرير مالي شامل: إيرادات، مصروفات، صافي الرصيد.
- سجل مدفوعات كامل لكل ولي أمر مع إمكانية الطباعة.

### 3.6 الإحصائيات والرسوم البيانية
- لوحة تحكم (Dashboard) مختلفة لكل دور:
  - **المدير:** إحصائيات عامة (عدد الطلاب، نسبة الحضور، الأداء الأكاديمي، الوضع المالي).
  - **المدرس:** أداء فصوله، نسب النجاح، الحضور.
  - **الطالب/ولي الأمر:** أداء شخصي، حضور، مدفوعات.
- رسوم بيانية تفاعلية (أعمدة، دوائر، خطوط) لعرض:
  - توزيع الطلاب حسب الصفوف
  - نسب الحضور والغياب
  - متوسط الدرجات لكل مادة/فصل
  - الوضع المالي الشهري
- تقارير قابلة للتصدير (PDF / Excel).

### 3.7 الإشعارات الفورية
- إشعارات داخل التطبيق (In-App Notifications) لكل الأدوار.
- تنبيهات تلقائية عند: غياب الطالب، رصد درجة جديدة، تحديث الجدول، استحقاق دفعة مالية، رسالة من الإدارة.
- مركز إشعارات (Notification Center) بسجل كامل قابل للتصفية والتحديد كمقروء.
- إمكانية إرسال إشعارات جماعية من الإدارة (لكل المدرسة / صف معيّن / دور معيّن).

### 3.8 ميزات الذكاء الاصطناعي (لاحقًا ضمن خارطة الطريق)
- تحليل أنماط الحضور والتنبؤ بالطلاب المعرّضين لخطر التسرب الدراسي.
- توصيات ذكية لتحسين أداء الطالب بناءً على درجاته.
- مساعد ذكي (Chat Assistant) يجيب عن استفسارات أولياء الأمور والطلاب.
- توليد تقارير نصية تلقائية (ملخص أداء) لكل طالب.
- اكتشاف تعارضات الجدول واقتراح حلول تلقائيًا.

## 4. المتطلبات غير الوظيفية (Non-Functional Requirements)

### 4.1 التصميم والهوية البصرية
- تصميم حديث، بسيط، احترافي (Modern Flat / Material-inspired).
- **الألوان الأساسية:**
  - 🔴 الأحمر — للتنبيهات، الحالات الحرجة (غياب، متأخر، مستحق دفع)
  - 🟢 الأخضر — للنجاح، الحالات الإيجابية (حاضر، ناجح، تم الدفع)
  - 🔵 الأزرق — اللون الأساسي للهوية (الشريط العلوي، الأزرار الرئيسية، الروابط)
- خط عربي واضح وحديث (مثل Cairo أو Tajawal).
- دعم كامل للغة العربية (RTL) مع إمكانية دعم الإنجليزية مستقبلًا.
- شعار المدرسة ظاهر في الشريط العلوي وفي الشهادات المصدَرة.

### 4.2 الاستجابة (Responsive Design)
- توافق كامل مع الجوال، التابلت، وشاشات الحاسوب.
- قوائم قابلة للطي (Collapsible Sidebar) على الشاشات الصغيرة.
- جداول قابلة للتمرير أفقيًا على الجوال دون كسر التصميم.

### 4.3 الأداء
- زمن تحميل الصفحة الرئيسية أقل من ثانيتين.
- تحميل البيانات بشكل تدريجي (Pagination / Lazy Loading) للقوائم الطويلة.

### 4.4 الأمان
- تشفير كلمات المرور.
- التحقق من صلاحيات كل طلب قبل تنفيذه.
- نسخ احتياطي دوري لقاعدة بيانات RealmDB.
- سجل تدقيق (Audit Log) للعمليات الحساسة (حذف، تعديل درجات، عمليات مالية).

### 4.5 قابلية التوسع
- بنية كود منظمة (Modular Structure) تسمح لاحقًا بإضافة إطار عمل (مثل React) دون إعادة بناء كاملة.
- فصل واضح بين طبقة العرض (UI) وطبقة البيانات (RealmDB Layer) وطبقة المنطق (Business Logic).

## 5. البنية التقنية المقترحة (المرحلة الأولى)

| الطبقة | التقنية |
|---|---|
| الواجهة الأمامية | HTML5 + CSS3 + JavaScript (Vanilla) |
| قاعدة البيانات | RealmDB (محلية) |
| الرسوم البيانية | مكتبة خفيفة (مثل Chart.js) عبر CDN، أو رسم يدوي بـ Canvas/SVG |
| توليد PDF | مكتبة JS خفيفة (مثل jsPDF) عبر CDN |
| الإشعارات | نظام داخلي مبني على RealmDB + تحديث لحظي عبر Realm Sync/Listeners |
| الأيقونات | مكتبة أيقونات SVG مفتوحة المصدر |

## 6. الكيانات الأساسية لقاعدة البيانات (Data Model - مبدئي)

- **User** (المستخدم): id, name, role, email, password_hash, phone, photo
- **Student** (طالب): id, userId, classId, parentId, birthDate, gender, status
- **Teacher** (مدرس): id, userId, specialization, subjects[]
- **Parent** (ولي أمر): id, userId, studentsIds[]
- **Class** (فصل): id, name, level, section
- **Subject** (مادة): id, name, classId, teacherId, weeklyHours
- **Schedule** (جدول): id, classId, subjectId, teacherId, day, period
- **Attendance** (حضور): id, studentId, date, status, subjectId
- **Grade** (درجة): id, studentId, subjectId, term, score, maxScore, type
- **Certificate** (شهادة): id, studentId, term, generatedDate, fileUrl
- **Payment** (دفعة): id, studentId, amount, dueDate, status, paidDate
- **Expense** (مصروف): id, category, amount, date, description
- **Notification** (إشعار): id, userId, title, message, type, isRead, createdAt

## 9. ملاحظات ختامية
هذه الوثيقة تمثل نقطة البداية لتطوير النظام، ويُنصح بمراجعتها وتحديثها بشكل دوري مع تقدم التطوير الفعلي. يمكن البدء ببناء النموذج الأولي (Prototype) للشاشات الأساسية (تسجيل الدخول + لوحة تحكم المدير) كأول خطوة عملية.
