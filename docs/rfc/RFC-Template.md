## 1. Problem Statement

What problem or gap does this change address? State the context and the business or architectural driver. Reference the affected governance rules or architecture documents.

## 2. Proposal

Describe the proposed change precisely:

- What is changing.
- Which bounded contexts, contracts, migrations, or processes are affected.
- How it aligns with the Architecture Principles and Dependency Rules.

## 3. Alternatives Considered

List rejected alternatives and the reason each was rejected.

## 4. Impact Analysis

| Impact Area | Description |
|---|---|
| Bounded Context Map | Contexts/relationships affected |
| Published Contracts | Contracts/versions affected |
| Data / Migration | Schema or data impact |
| Security | Security review needed |
| AI | AI governance impact |
| Documentation | Documents to update |
| Timeline | Effort estimate |

## 5. Decision

State the recommended decision and the approval path required (per `docs/governance/Decision-Matrix.md`). Confirm whether an ADR is required.

## 6. Implementation Notes

Summarize what must happen after approval:

- ADR to record.
- Documents to update.
- Compliance checks to run.
- Freeze status effect (Documentation Freeze).
